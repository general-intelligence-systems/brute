# How Reasoning Works

A reasoning model does not only answer: it thinks first, and the provider hands
that thinking back alongside the answer. It is not decoration. When the model
answered with a tool call, the thinking is *why it called that tool*, and the
next request in the loop has to carry it or the model resumes without the part
that made the decision.

Brute keeps it on the message and sends it back.

The key files:

- `lib/brute/messages.rb` — `Brute::Reasoning`, and the `reasoning` field on `Brute::Message`
- `lib/brute/message_transport/*.rb` — one per provider library: reasoning in, reasoning out

## Why it matters

Every provider says the same thing in its own words.

**OpenAI** ([platform docs — reasoning][openai-reasoning]) on function calling:

> we highly recommend you pass back any reasoning items returned with the last
> function call (in addition to the output of your function)

and, where several calls run in sequence, to include "all reasoning items,
function call items, and function call output items, since the last `user`
message" — "just ensure all items between the last user message and your
function call output are passed into the next response untouched."

**Anthropic** ([`ThinkingBlockParam`][anthropic-thinking-param], from the Ruby
SDK's own model definitions):

> The `signature` value of this thinking block, exactly as returned by the API
> in a previous response. Used to verify that the block was generated by
> Claude.
>
> Thinking blocks must be passed back unmodified and in their original order; a
> modified block results in a 400 `invalid_request_error`.

and on [`ThinkingBlock#signature`][anthropic-thinking-block]: "When passing
thinking blocks back to the API (required when using tools with extended
thinking), pass them back exactly as received, with this field intact."

**OpenRouter** ([reasoning tokens][openrouter-reasoning]): reasoning comes back
as a plaintext `reasoning` string and as a structured `reasoning_details` array,
and to preserve it you pass back either the string or "the complete
`message.reasoning_details` array unmodified" —

> The entire sequence of consecutive reasoning blocks must match the outputs
> generated by the model during the original request; you cannot rearrange or
> modify the sequence.

Two things follow, and they shape the design:

1. **Reasoning is not just text.** It comes with an opaque signature the
   provider verifies. Text alone cannot be sent back.
2. **It has to survive the round trip**, not merely be recorded.

## `Brute::Reasoning`

```ruby
Reasoning       = Data.define(:blocks)
Reasoning::Block = Data.define(:type, :text, :signature, :format, :id)
```

A sequence, in the order the model produced it, because that is what both
providers ask for. Each block names its own `format` — who signed it — and its
`type`: `:text` for thinking that can be read, `:encrypted` and `:redacted` for
a payload that is not ours to read (Anthropic's `redacted_thinking`, an
encrypted reasoning item) and matters only in that it goes back whole.

`Reasoning.build` answers `nil` when there is nothing to keep, so a provider
that reports no thinking costs nothing. `Brute::Message` carries one and
coerces what it is given — a `Reasoning`, a `String`, or the hash a
conversation read back off disk.

### Why the format is on it

The log is provider-agnostic: a conversation can be replayed against anyone,
and often is. But a signature only means something to the provider that issued
it. Anthropic verifies its own and 400s on anything it cannot; OpenRouter names
the format (`"anthropic-claude-v1"`, `"openai-responses-v1"`) precisely because
the details are only valid against the provider that produced them.

So `Reasoning#signed_by?(format)` is the question every transport asks before
sending anything opaque: *is this mine?* If it is, the blocks go back whole and
in order. If it is not, the text survives where the wire has a plain field for
it, and the signature is dropped rather than asserted. Switch model mid-
conversation and the thinking stays in the log and in traces — it just stops
claiming to be verifiable.

The shape mirrors [`RubyLLM::Thinking`][ruby_llm-thinking], which models text
and signature for the same reason:

> The provider's opaque signature or encrypted reasoning payload for the
> thinking block

## Per provider

Each transport knows one library, so each knows where its library puts
reasoning and what the wire wants back.

| transport | in | out |
| --- | --- | --- |
| `open_router` | `reasoning_details`, each with its own format; or `reasoning` as plain text | `reasoning` string always, `reasoning_details` whole and in order when signed |
| `anthropic` | every `thinking` and `redacted_thinking` block, in order | `thinking` / `redacted_thinking` blocks, first, before text and `tool_use` — only when Anthropic signed them |
| `ruby_llm` | [`message.thinking`][ruby_llm-message] — a `RubyLLM::Thinking` | `RubyLLM::Thinking.build(text:, signature:)` |
| `openai` | — | — |
| `ruby_open_ai` | `hash[:reasoning]`, which an OpenAI-compatible proxy may report | — |
| `llm` | [`message.reasoning_content`][llm-message] | — |

Three details are load-bearing rather than incidental:

**Order, for Anthropic.** Thinking goes back *first*, ahead of the text and the
`tool_use` blocks, because the sequence is part of what is verified.
`thinking_blocks` sends nothing when the blocks are not Anthropic's — an
unverifiable block is a 400, and no thinking beats a failed request — and the
reasoning-only branch does not emit an empty text block, which Anthropic also
rejects.

**Both forms, for OpenRouter.** The plaintext string is what a reader sees; the
`reasoning_details` array is what carries the signatures. The string goes
always; the array goes whole, or not at all.

**Nothing, for chat completions.** Neither `ChatCompletionMessage` nor the
assistant message param in the `openai` gem has a reasoning field — reasoning
items belong to the Responses API, which these transports do not speak — so
`openai` and `ruby_open_ai` send none back. `ruby_open_ai` still reads it on the
way in, because an OpenAI-compatible proxy may report it and keeping it costs
nothing.

## An empty completion is an error

Before this, `wrap` sliced reasoning away as a provider extra. A reasoning model
that spent its output on thinking and said nothing else therefore produced:

```json
{"role":"assistant"}
```

— an assistant message with no content, no tool calls and no thinking. Nothing
raised. The tool loop stopped, because the last message was not a tool result;
`has_reply?` was true, because the role was `:assistant`; and the caller asking
what the reply *said* got `nil`. A turn was lost in silence, having been paid
for.

So `Brute::MessageTransport::OpenRouter::EmptyCompletion` is raised when a
completion has no content, no tool calls **and** no reasoning — the case where
the provider was paid for an answer and there is none. Reasoning-only is no
longer that case: it is a message, with the thinking on it.
